# Калории

Простой дневник калорий в виде PWA без рекламы и лишних функций. Работает офлайн: данные лежат в браузере (IndexedDB). На своём сервере можно включить аккаунты — тогда дневник синхронизируется между устройствами, а справочник продуктов становится общим для всех пользователей.

- **Дневник** — записи за день, остаток до цели, белки/жиры/углеводы.
- **Справочник** — три раздела: продукты, рецепты, готовая еда. Тот же вид открывается по «+» в дневнике, только там тап по еде сразу добавляет её в день. Продукты и готовая еда ищутся ещё и в Open Food Facts; рецепты — только ваши.
  - **Продукты** — КБЖУ с этикетки на 100 г или на порцию. Если указан вес порции, еду можно добавлять порциями.
  - **Рецепты** — соберите блюдо из сырых продуктов, укажите вес готового и получите КБЖУ на 100 г. Можно указать число порций — тогда блюдо записывается порциями без взвешивания.
  - **Готовая еда** — ланчи, доставка, полуфабрикаты: КБЖУ на порцию, вес не обязателен.
- **Open Food Facts** — сканер штрихкодов (камера или ввод цифр) и поиск по названию и производителю. Найденное КБЖУ подставляется в форму, его стоит сверить с этикеткой. Свои продукты можно отправить в базу OFF под своим аккаунтом.
- **Вес** — запись веса и график за месяц, 3 месяца или всё время. Последний вес обновляет расчёт цели.
- **Цель** — расчёт по формуле Миффлина — Сан-Жеора с дефицитом, можно задать вручную. Выгрузка в CSV для Excel (дневник, итоги по дням с весом, вес, справочник) за неделю, месяц, всё время или выбранные даты. Резервная копия в JSON.

## Разработка

```bash
npm install
npm run dev      # dev-сервер
npm test         # тесты расчётов и базы
npm run build    # сборка в dist/
npm run preview  # проверка production-сборки с service worker
```

## Публикация

Сайт: https://coldgleb.github.io/calories/

Workflow `.github/workflows/deploy.yml` прогоняет тесты, собирает и публикует сайт на GitHub Pages при каждом пуше в `main`.

## Свой сервер с аккаунтами (Docker)

Образ — [PocketBase](https://pocketbase.io) (база, регистрация и вход, права доступа, админка), который раздаёт и само приложение, и API на одном адресе.

```bash
cp .env.example .env   # задайте email и пароль администратора
docker compose up -d --build
```

Приложение откроется на порту `8080`, админка PocketBase — `/_/` (вход — данные из `.env`). Данные сервера лежат в `./pb_data` — эту папку и нужно бэкапить (или включите бэкапы в админке).

Как устроено:
- **Регистрация** открыта: email и пароль (от 8 символов), без подтверждения почты. Ограничение частоты запросов PocketBase включено.
- **Дневник, рецепты, вес и цель** — личные, видны только владельцу.
- **Продукты и готовая еда** — общий справочник: добавлять могут все, изменять и удалять — автор и администратор. Чужой продукт можно скопировать к себе.
- **Администратор приложения**: в админке `/_/` → коллекция `users` → поле `role` = `admin`. Он может править любой общий продукт.
- **Забытый пароль**: письма не настроены, сбросьте пароль пользователю в админке.
- Приложение работает офлайн и синхронизируется при появлении сети. При первом входе на устройстве с данными можно объединить их с аккаунтом или взять данные из аккаунта. При выходе данные удаляются с устройства.

Перенести на сервер без интернета:

```bash
docker compose build
docker save calories:latest | gzip > calories.tar.gz
# на сервере, рядом с docker-compose.yml и .env:
docker load < calories.tar.gz
docker compose up -d --no-build
```

**Нужен HTTPS.** Камера (сканер штрихкодов), установка на экран «Домой» и офлайн-режим работают только в защищённом контексте: `https://` или `localhost`. Поставьте перед контейнером обратный прокси с сертификатом (Caddy, Traefik, nginx + Let's Encrypt) или используйте Tailscale / Cloudflare Tunnel.

Версия на GitHub Pages работает без сервера: аккаунтов там нет, всё хранится в браузере.
