# Калории

Простой дневник калорий в виде PWA: без аккаунтов, рекламы и лишних функций. Данные хранятся только в браузере (IndexedDB).

- **Дневник** — записи за день, остаток до цели, белки/жиры/углеводы.
- **Готовая еда** — КБЖУ с этикетки на порцию (вес порции не обязателен) и сколько порций съели — сразу в дневник, с сохранением в справочник по желанию.
- **Продукты** — личный справочник. КБЖУ вводится с этикетки на 100 г или на порцию. Если указан вес порции, еду можно добавлять порциями.
- **Рецепты** — соберите блюдо из сырых продуктов, укажите вес готового и получите КБЖУ на 100 г. Можно указать число порций — тогда блюдо записывается порциями без взвешивания. Рецепт ищется как обычный продукт.
- **Open Food Facts** — сканер штрихкодов (камера или ввод цифр) и поиск по названию и производителю. Найденное КБЖУ подставляется в форму, его стоит сверить с этикеткой. Свои продукты можно отправить в базу OFF под своим аккаунтом.
- **Вес** — запись веса и график за месяц, 3 месяца или всё время. Последний вес обновляет расчёт цели.
- **Цель** — расчёт по формуле Миффлина — Сан-Жеора с дефицитом, можно задать вручную. Выгрузка в CSV для Excel (дневник, итоги по дням с весом, вес, справочник) за неделю, месяц, всё время или выбранные даты. Резервная копия в JSON.

## Разработка

```bash
npm install
npm run dev      # dev-сервер
npm test         # тесты расчётов и базы
npm run build    # сборка в dist/
npm run preview  # проверка production-сборки с service worker
```

## Публикация

Сайт: https://coldgleb.github.io/calories/

Workflow `.github/workflows/deploy.yml` прогоняет тесты, собирает и публикует сайт на GitHub Pages при каждом пуше в `main`.

## Запуск в Docker

```bash
docker compose up -d --build
```

Приложение откроется на порту `8080`. Образ собирается из исходников: тесты, сборка и nginx.

Перенести на сервер без интернета можно готовым образом:

```bash
docker compose build
docker save calories-web:latest | gzip > calories-web.tar.gz
# на сервере, рядом с docker-compose.yml:
docker load < calories-web.tar.gz
docker compose up -d --no-build
```

**Нужен HTTPS.** Камера (сканер штрихкодов), установка на экран «Домой» и офлайн-режим работают только в защищённом контексте: `https://` или `localhost`. По адресу вида `http://192.168.1.10:8080` приложение откроется, но без этих функций. Поставьте перед контейнером обратный прокси с сертификатом (Caddy, Traefik, nginx + Let's Encrypt) или используйте Tailscale / Cloudflare Tunnel.

Данные по-прежнему хранятся в браузере каждого устройства. Синхронизация через сервер — следующий этап.

Установка на телефон: «Установить приложение» (Android/Chrome) или «Поделиться → На экран „Домой“» (iOS/Safari).
